# M8 bond core implementation review (`sabiquant::bonds`)

Review completed 2026-10-16, Asia/Bangkok, on the local worktree based on
`8bfa292`, before the M8 bond core tranche was committed. The implementation
of the [bond core contract](M8_BOND_CORE_CONTRACT.md), the per-100 exact
binary64 quote kernel (`src/bonds/quote.rs`), the shared M4 rate-kernel helpers
(`src/rates.rs`), the shared M7 cashflow helpers (`src/cashflows.rs`), and the
documentation were reviewed against `FR-BOND-01..10`.

## Code review

No code defect was found.

- **Single-rounding binary64 per-100 quote kernel (`src/bonds/quote.rs`).**
  For `100 * X / face = (25 * M_X / M_F) * 2^(e_X - e_F + 2)` and
  `face * price / 100 = (M_F * M_P / 25) * 2^(e_F + e_P - 2)`, numerator
  `A < 2^106` and denominator `B < 2^53`. Computing `k = floor(log2(A / B))`
  first determines the exact binade `top = k + E`. For `-1075 <= top <= 1023`,
  the target unit exponent `u = max(top - 52, -1074)` and shift `s = E - u`
  satisfy `k + s = top - u in [-1, 52]`. Consequently `scaled_num < 2^106`,
  `scaled_den < 2^107`, and `2 * remainder < 2^108` all fit in native `u128`
  without overflow. All 139 / 139 production regions in `src/bonds/quote.rs`
  are covered (`100.00%`).
- **Two-stage pricing plan and M4/M7 kernel reuse (`src/bonds.rs`).**
  `BondPricingPlan::new` resolves coupon/redemption entitlement,
  earned-minus-detached accrued interest, and direct `settlement -> payment`
  discount horizons once under a shared `u64` accrual work ledger (`1` unit for
  discount anchor, `1` + ICMA overlaps / Business252 span days for partial
  coupon accrual when `start < S < end` and for buyer-entitled discount
  horizons). `BondPricingPlan::evaluate` reuses `validate_rate` and
  `present_value_at` from `src/rates.rs` without cloning `AccrualConvention` or
  repeating date/calendar queries.
- **Independent oracle and hand suites.**
  All 18,152 rows of `validation/fixtures/bonds/bond-core-oracles.fixture`
  (generated by `validation/generator/bond_core_oracles.py` using Python bit
  fields, `Fraction`, `Decimal`, and civil dates without Rust or QuantLib
  output) and all 7 tests in `tests/bonds_core_hand.rs` pass in debug and
  release modes.

## Integrator findings

- **Lint expectation on `Bond::fixed_rate`.** `Bond::fixed_rate` takes 7
  arguments, which is at (not above) Clippy's `too_many_arguments` threshold of
  7. An initial `#[expect(clippy::too_many_arguments)]` attribute was removed
  to satisfy `-D unfulfilled-lint-expectations`.
- **Binade-carry overflow at `top == 1023`.** In `src/bonds/quote.rs`,
  `f64::from_bits(f64::MAX.to_bits() - 2)` paired with
  `f64::from_bits(100.0_f64.to_bits() - 2)` (for `per_100_from_amount`) and
  `f64::from_bits(100.0_f64.to_bits() + 2)` (for `amount_from_per_100`)
  produces an exact pre-rounding binade `top == 1023` whose retained 53-bit
  significand `2^53 - 1` rounds up to `2^53`, exercising `rounded_top > 1023`
  and bringing `src/bonds/quote.rs` production region coverage to 139 / 139
  (`100.00%`).
