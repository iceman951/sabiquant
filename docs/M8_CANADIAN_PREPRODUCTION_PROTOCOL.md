### Elementary observations and portable exact-stage expectations

ln/ln1p/exp denote actual native observations under the explicit conditional
primitive hypotheses. Their contract does not prescribe correctly-rounded ideal
bits or one macOS bit snapshot for every platform. The numerical corpus must
separate certified ideal elementary intervals/profile checks from exact
represented-input exponent/PV/risk/reduction/residual stages. The latter may
supply explicit represented g/factor seeds as primitive INPUTS and compare exact
integer/RNE outputs. Such seeds remain primitive controls unless independently
bound to a complete dated state; they cannot masquerade as actual public
reachability. A production-linked checker compares actual elementary outputs to the certified
ideal interval WITH the explicit primitive allowance, rather than requiring
the native result to lie inside the narrow ideal enclosure itself. Exact
stages compare against supplied seeds; public composed observations use
independently propagated ideal bounds. A public compound input with one exact
expected price/error/guard classification must be certified stable across the
allowed primitive-error interval. Otherwise freeze seeded exact-stage controls
and predeclare a qualified composed interval or bounded classification set;
do not use an unrestricted error wildcard or infer public branch reachability
from the seed alone. Platform snapshots retain their exact platform scope.
This separation must preserve output bindings and cannot omit validation of
the composed kernel or turn elementary measurements into universal accuracy.

Use unchanged schema1 and the actual [shared Rust reader](../tests/support/fixture.rs),
including its eleven required headers and equal-width records. The new corpus
and byte attestor require canonical LF bytes ending in LF. The unchanged reader
itself accepts LF or CRLF; its successful parse alone cannot enforce this stricter
new artifact-byte rule.
Each new corpus must additionally pin actual generator bytes, the entire
adopted contract and incorporated component hashes, extracted FR-CAD rows,
body/records and exact input bytes with SHA256 and FNV64. Actual UTC/Python/
platform metadata describes generation. Output creation is exclusive;
`--check` reproduces expected bytes while preserving generation metadata.

Root independently approves the complete columns, profile discriminator and
semantic input fields per corpus; an unknown schema fails closed. Canonical
input fingerprints include complete financial definitions (including EOM,
T, policy/selection, original ordinal and evidence kind/bits/bounds), actual
operation and its parameters. They exclude expected values, derived amounts,
reachability/shape/result labels, provenance conclusions and arbitrary row IDs.
A changed expected column cannot disguise duplicate financial inputs.

Report record count, unique serialized input count and operation-specific
primitive diversity separately. Canonical decimal values and negative zero
follow the adopted identity rules; spelling aliases do not become additional
independent financial inputs. Repeated geometry across risk getters or three
price bases is labelled as such. Caps are explicit operation inputs even
though they do not change financial Eq/Hash. Profile counts must match the
actual approved profile field and cannot be assumed from generator comments.

## Complete gate and integrity controls

The future new attestor must run all producer `--check` commands, compile a
small driver including the actual unchanged shared reader, parse every new
corpus and optionally all historical fixtures, verify root-approved schema/
input lists and all pins/censuses, and byte-guard all consumed inputs through
the run. It writes real command/status/log/hash evidence to a fresh external
directory. Missing corpus, unknown schema, skipped reproduction, changed input
or failed reader cannot close the complete gate. An interim subset is labelled
interim. This gate proves artifact identity and actual reader acceptance,
not financial correctness, Canadian runtime behavior or wider M8 acceptance.

Tool integrity controls must include wrong contract/requirements/generator/
body pins, profile/count drift, duplicate semantic input with a changed answer,
answer-column substitution, unknown/malformed schema, wrong source bytes,
CRLF/report normalization, output overwrite/alias refusal, failed subprocess
and source mutation during the run. Synthetic integrity fixtures remain
separate from financial cases. Pre-acceptance corrections preserve earlier
bytes/failures and receive review; accepted generators/expectations then freeze.

After production, connect each accepted corpus to the actual public operations
or attested private kernel, with explicit output bindings. Runtime assertions
must kill meaningful semantic faults: valuation/payable substitution, A/AI
swap, duplicate terminal, missing odd fragment, wrong f12 scaled log,
rounded lambda, inward/open guard, source PV double rounding, raw-before-
normalize, ideal-H replacement of selected MM risk, ideal-image target
precheck, hidden final solve callback, wrong ordinal, hidden cash quantizer,
endpoint-only Exact, missing L provenance and lost cancellation. Compile
failure alone is not a semantic kill. Then run the complete native regression,
